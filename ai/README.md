# AI 文档中心

本目录保存项目的需求、设计、任务、测试和决策记录，为 AI 开发提供稳定、可追踪的上下文。

## 目录规则

- 每次实质性迭代使用 `iterations/NNN-short-name` 目录。
- `NNN` 从 `001` 开始递增，使用三位数字。
- `short-name` 使用小写英文和连字符，简要描述迭代目标。
- 已完成的历史迭代不得覆盖；变更通过新迭代说明与前一版本的差异。
- 所有需求和设计文档统一使用 UTF-8 编码的 Markdown。

## 每个迭代的标准文档

- `requirements.md`：本迭代要解决的问题、范围、规则和验收标准。
- `architecture-design.md`：系统结构、模块边界、数据流、约束和演进方案。
- `tasks.md`：可执行任务、状态和验证记录。
- `test-plan.md`：测试范围、关键场景和完成标准。
- `decisions.md`：重要产品或技术决策、原因、替代方案和复查条件。

## 状态约定

- `Draft`：仍在讨论，不可直接作为实现依据。
- `Approved`：已确认，可进入实现。
- `Implemented`：已完成实现，等待完整验证。
- `Verified`：已通过约定测试并完成验收。

## AI 工作流程

1. 定位当前迭代并读取全部标准文档。
2. 将需求拆解到 `tasks.md`，明确每项任务的验证方式。
3. 发现冲突或缺失决策时，先写入 `decisions.md`。
4. 修改代码时同步维护测试和文档。
5. 完成后更新状态、验证结果和遗留问题。

新迭代可从 [迭代模板](templates/iteration-template.md) 开始创建。
