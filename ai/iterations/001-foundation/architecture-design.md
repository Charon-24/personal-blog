# 001 Foundation 架构设计

> 文档状态：Approved  
> 对应需求：V1.1  
> 更新日期：2026-09-05

## 1. 设计目标

- 支撑多用户博客和笔记的首期功能。
- 将用户数据隔离和内容访问权限作为系统级约束。
- 保持本地开发、AI 调试、自动化测试和低流量部署足够简单。
- 通过清晰模块边界保留未来演进到微服务的能力。

## 2. 当前约束

- 前端使用 Vue，后端使用 Spring Boot。
- 预计上线用户量较少，无独立扩容和多团队发布需求。
- 项目主要用于完整的 Vibe Coding 实践，需要缩短生成、验证和纠错周期。
- 本迭代不确定框架小版本、数据库、认证、持久化和部署组件。

## 3. 架构决策

首期采用渐进式模块化单体：后端以一个 Spring Boot 应用作为部署单元，业务代码按领域边界组织。暂不采用 Spring Cloud Alibaba，也不引入 Nacos、Gateway、OpenFeign、Sentinel、RocketMQ 或 Seata。

该决策优先保证业务闭环、权限正确性和测试效率，同时要求模块间通过明确的应用服务协作，禁止直接跨模块修改内部数据。

## 4. 后端模块边界

| 模块 | 核心职责 | 主要依赖方向 |
| --- | --- | --- |
| 用户 | 注册、登录、账号状态、角色和用户资料 | 公共基础 |
| 内容 | 博客、笔记、草稿、分类、标签、归档 | 用户、访问授权、媒体 |
| 访问授权 | 四级权限、指定用户授权和统一访问判断 | 用户、公共基础 |
| 互动 | 点赞、评论、回复和互动通知 | 用户、内容、访问授权 |
| 媒体 | 头像、封面、正文图片及访问控制 | 用户、访问授权 |
| 平台管理 | 用户治理、内容治理、配置和审计 | 通过各模块公开的管理用例协作 |
| 公共基础 | 异常、校验、日志和无业务归属的基础能力 | 不反向依赖业务模块 |

模块可以共享同一部署单元和数据库实例，但业务数据必须保留明确归属。跨模块操作通过应用服务或领域事件表达，不直接访问其他模块的内部实现。

## 5. 前端应用边界

- 公共博客前台：面向游客和登录用户的公开阅读与搜索体验。
- 用户中心：面向创作者的个人资料、内容、权限、媒体和互动管理。
- 平台管理端：面向管理员的用户治理、内容治理、配置和审计。

首期是否构建为单个 Vue 工程由后续技术选型决定，但路由、权限和状态应按照上述区域隔离。

## 6. 数据隔离

- 用户数据必须保存不可伪造的所有者标识。
- 服务端从认证上下文获取当前用户，不使用客户端提交的用户编号作为最终授权依据。
- 详情、列表、批量操作、搜索、统计、缓存、媒体和后台任务都必须执行归属或可见性校验。
- 普通用户只能管理本人数据；平台管理员的跨用户处置必须通过专用管理用例并记录审计信息。
- 自动化测试必须包含篡改资源编号、跨账号访问和权限变更后继续访问等场景。

## 7. 内容权限模型

| 等级 | 允许访问者 |
| --- | --- |
| 公开 | 游客和所有登录用户 |
| 登录可见 | 任意状态正常的登录用户 |
| 指定用户可见 | 作者和有效授权名单内的用户 |
| 仅自己可见 | 内容作者本人 |

- 笔记默认仅自己可见。
- 权限收紧后必须立即影响详情、列表、搜索、缓存、媒体和互动入口。
- 无权限响应不得泄露内容标题、作者私密资料、互动数据或资源是否真实存在。

## 8. 互动一致性

- 同一用户对同一博客最多存在一个有效点赞。
- 点赞与取消点赞必须支持重复请求而不产生错误计数。
- 评论和回复必须关联所属博客，并在写入前复核博客状态、访问权限和评论开关。
- 删除父评论时保留必要占位，避免破坏仍然有效的回复上下文。
- 点赞数和评论数等汇总值必须能够与有效明细核对和修复。

## 9. 部署形态

首期目标形态为一个 Vue Web 应用、一个 Spring Boot 应用和必要的数据存储。开发环境可以在后续通过本地编排统一启动，但本迭代不生成编排文件或锁定基础设施。

## 10. 微服务演进路线

只有满足以下至少一项条件时才重新评估拆分：

- 某模块需要独立扩容或独立发布。
- 出现稳定、清晰且可自治的服务边界。
- 多团队需要独立负责不同业务域。
- 项目进入明确的微服务专项练习阶段。

优先考虑拆分通知、搜索或媒体等弱事务模块。演进后按需使用：

- Nacos：服务发现和集中配置。
- Spring Cloud Gateway：统一服务入口。
- OpenFeign：必要的同步服务调用。
- Sentinel：限流、熔断和降级。
- RocketMQ：通知、索引等异步事件。
- Seata：仅在本地事务和最终一致性方案不能满足真实需求时评估。

## 11. 本迭代不做

- 不生成 Spring Boot 或 Vue 工程。
- 不定义具体 API、数据库表和依赖版本。
- 不初始化微服务组件、容器编排或云资源。
- 不以预估流量为由提前建设分布式复杂度。
