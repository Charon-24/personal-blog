# 个人博客网站需求文档

> 文档版本：V1.1  
> 项目名称：Personal Blog  
> 项目状态：需求初稿  
> 前端架构：Vue  
> 后端架构：Spring Boot  
> 具体技术栈：待技术设计阶段确定

## 1. 项目概述

### 1.1 项目背景

建设一个支持多用户独立创作与展示的博客网站。每位注册用户均可维护自己的头像、用户名等个人资料，创建博客或笔记，并通过权限等级控制内容的可见范围。用户之间可以围绕公开或已获授权的博客进行点赞、评论和回复。平台应在保证用户数据隔离和访问安全的前提下，兼顾内容阅读体验、创作效率、互动体验、搜索引擎友好性及后续扩展能力。

### 1.2 项目目标

- 提供简洁、舒适且适配多终端的博客与笔记阅读体验。
- 支持用户注册、登录及个性化资料维护。
- 支持博客和笔记从草稿、预览到发布、归档的完整生命周期管理。
- 确保不同用户的数据在查询、修改、删除和统计等场景中严格隔离。
- 支持内容可见权限配置，满足公开分享、受限分享和私人记录等需求。
- 通过点赞、评论和回复形成基础内容互动闭环。
- 通过分类、标签、归档和搜索帮助访客快速发现内容。
- 提供安全、易用的博客管理后台。
- 前后端职责清晰，便于后续替换组件和扩展业务能力。
- 为关注、订阅、统计、多语言等增强功能预留扩展空间。

### 1.3 首期范围

首期以“可注册、可创作、可管理、可阅读、可互动”为核心，完成用户账号与资料、博客与笔记管理、用户级数据隔离、内容权限、站点展示、基础搜索、点赞、评论、回复及平台管理。关注、私信、商业化、团队协作等复杂社交能力暂不作为首期重点。

## 2. 用户角色与权限

### 2.1 游客（未登录用户）

- 浏览已发布且公开的博客。
- 按分类、标签、归档时间筛选公开博客。
- 搜索公开博客。
- 查看平台介绍、友情链接及其他公开页面。
- 查看允许游客访问的用户主页和公开博客。
- 默认不能创作、点赞、评论或回复；若后续开放游客评论，需增加身份识别和反垃圾机制。

### 2.2 注册用户/创作者

- 注册、登录和退出账号。
- 设置并修改头像、用户名、个人简介等个人资料。
- 创建、编辑、预览、发布、下线及删除本人博客或笔记。
- 为本人内容设置访问权限。
- 管理本人内容的分类、标签、评论和媒体资源。
- 对有权访问的博客点赞、取消点赞、评论和回复。
- 管理本人发布的评论与回复，并处理本人内容下的互动。
- 查看仅属于本人的创作、互动和访问统计。

### 2.3 平台管理员

- 管理用户状态及平台公共配置。
- 对违规博客、笔记、评论和回复进行隐藏、下线或删除处理。
- 管理平台级分类、敏感词、举报和审核规则（如启用）。
- 查看平台运行统计和必要的审计记录。
- 管理员不得以普通业务功能任意修改用户私人内容；确需处置时应遵守平台规则并记录审计信息。

### 2.4 权限原则

- 未登录用户只能访问被明确设为公开的内容和公开接口。
- 登录用户只能管理本人资料、本人内容及本人产生的互动数据。
- 内容访问必须同时校验登录状态、内容权限等级、内容归属和内容状态。
- 任意资源的读取、修改、删除、导出和统计操作均不得仅依赖前端传入的用户标识。
- 管理类接口必须经过身份认证、资源归属和权限校验。
- 高风险操作应进行二次确认，并保留必要的操作记录。
- 平台管理员权限与普通用户权限应分离，并遵循最小权限原则。

## 3. 功能需求

### 3.1 用户账号与认证

- 支持用户注册、登录和安全退出。
- 注册时至少填写用户名、密码及用于账号验证或找回的联系方式，具体注册字段待确认。
- 用户名在平台内应保持唯一，并校验长度、字符范围及敏感词。
- 支持登录状态过期处理，过期后引导用户重新登录并尽量保留当前浏览位置。
- 支持修改密码；账号找回、邮箱/手机验证及第三方登录可分阶段建设。
- 连续登录失败达到阈值时，应触发限流、验证码或临时锁定等保护措施。

### 3.2 用户资料与个人主页

- 用户可上传、更换或恢复默认头像。
- 用户可设置用户名、个人简介、个人主页背景及公开的社交链接；首期必需项为头像、用户名和个人简介。
- 修改用户名时需校验唯一性，并限制频繁修改。
- 头像上传需校验格式、大小和内容安全；加载失败时显示默认头像。
- 个人主页展示用户主动公开的资料、公开博客及基础创作信息。
- 私密资料、联系方式、私人笔记及未授权内容不得出现在个人主页或公开接口中。
- 用户可预览自己的个人主页，并从个人中心进入创作与内容管理功能。

### 3.3 前台首页

- 展示网站名称、简介、头像或品牌标识。
- 展示有权访问的博客列表，默认按发布时间倒序排列。
- 博客卡片至少包含作者头像、用户名、标题、摘要、发布时间、分类、标签、权限提示和封面图（如有）。
- 支持分页或连续加载，具体交互形式待 UI 设计阶段确定。
- 可选展示置顶博客、推荐博客和热门博客。
- 提供清晰的导航入口，包括首页、分类、标签、归档、关于等。

### 3.4 博客详情

- 展示标题、正文、作者资料、发布时间、更新时间、分类、标签、阅读量和点赞数。
- 正文支持 Markdown 内容渲染。
- 支持代码块、语法高亮、图片、引用、列表、表格和超链接。
- 自动生成内容目录，并支持目录定位。
- 提供上一篇、下一篇博客入口。
- 支持复制博客链接及常见分享方式。
- 登录用户可对有权访问且允许互动的博客点赞或取消点赞，同一用户对同一博客最多形成一个有效点赞。
- 登录用户可发表评论、回复评论或回复其他回复；详情页应清晰展示回复关系。
- 内容作者可单独关闭某篇博客的评论功能。
- 无权访问、已下线或已删除的博客不得继续公开访问，也不得通过互动接口推断其内容信息。

### 3.5 博客与笔记创作

- 用户可选择内容类型：博客或笔记。
- 博客面向发布与分享，支持标题、摘要、正文、封面、分类、标签、权限和互动设置。
- 笔记面向个人记录，默认仅自己可见；用户可按需调整权限。
- 博客和笔记均支持 Markdown 编辑、预览、草稿保存、发布、下线和删除。
- 创作入口应清晰展示当前内容类型、保存状态及可见权限，降低误发布私人内容的风险。
- 用户只能查看、编辑、删除和发布本人创建的内容。
- 允许将笔记转换为博客或将博客转为笔记；转换前应提示权限和互动状态可能发生的变化。

### 3.6 内容访问权限

每篇博客或笔记可独立设置以下权限等级：

| 权限等级 | 可访问用户 | 典型用途 |
| --- | --- | --- |
| 公开 | 游客及登录用户 | 面向所有人发布的博客 |
| 登录可见 | 任意已登录用户 | 仅限平台用户阅读 |
| 指定用户可见 | 内容作者及被授权用户 | 小范围分享 |
| 仅自己可见 | 内容作者本人 | 私人笔记或未公开内容 |

- 新建博客的默认权限由用户设置或平台默认配置决定；新建笔记默认仅自己可见。
- 用户可在发布前确认权限，也可在发布后修改权限。
- 权限收紧后，原本有权访问的用户应立即失去访问权，相关缓存、搜索结果和分享预览应同步失效。
- 指定用户可见时，作者可添加或移除授权用户，并查看当前授权名单。
- 无权访问时统一返回不泄露内容详情的提示，不暴露标题、摘要、正文、作者私密信息或互动数据。
- 点赞、评论、回复、搜索、推荐、统计和消息通知必须遵循相同的内容访问权限。
- 内容作者始终可访问本人未删除的内容；平台管理员仅在合规审核或故障处置等授权场景下处理内容，并记录操作。

### 3.7 用户数据隔离

- 博客、笔记、草稿、分类、标签、媒体资源、授权名单和个人统计均归属于明确的用户。
- 用户只能管理本人数据，不得通过修改请求参数、资源编号或接口地址访问其他用户的非公开数据。
- 用户自定义分类和标签默认仅在本人创作空间内生效；平台公共分类如需提供，应与用户分类明确区分。
- 文件上传、导出、回收站、搜索、统计和批量操作同样需要执行用户归属校验。
- 后台任务、缓存和日志处理不得造成不同用户之间的数据串读或错误展示。
- 管理员查看或处置用户数据时应受角色权限限制，并记录操作人、原因、目标和结果。
- 用户注销或数据导出功能的范围、保留策略与合规要求在上线前明确。

### 3.8 分类与标签

- 一篇博客或笔记归属一个主要分类；是否支持多分类在详细设计阶段确定。
- 一篇博客或笔记可关联多个标签。
- 游客可查看公开分类、标签及对应公开博客数量。
- 支持进入分类或标签详情页查看当前用户有权访问的关联内容。
- 用户可新增、编辑、排序和删除本人的分类或标签。
- 删除已被使用的分类或标签时，应提示影响范围并要求重新归属或确认处理方式。

### 3.9 内容归档

- 按年份和月份聚合当前访问者有权查看的已发布博客。
- 展示博客标题、作者和发布时间。
- 点击博客标题可进入详情页。
- 用户个人中心可分别查看本人的博客归档和笔记归档。

### 3.10 搜索

- 支持按博客标题、摘要、正文、作者或标签关键字搜索。
- 游客搜索结果仅包含已发布且公开的博客；登录用户可额外搜索本人有权访问的内容。
- 用户可在个人中心搜索自己的博客、笔记和草稿。
- 搜索服务必须在返回结果前执行内容状态和访问权限过滤。
- 搜索结果应展示关键字命中信息或摘要。
- 支持无结果提示、搜索历史或热门搜索等后续增强能力。

### 3.11 平台关于页面

- 展示平台介绍、使用规则、联系方式及其他公共信息。
- 内容支持由平台管理员在后台维护。
- 联系方式应允许配置是否公开，避免敏感信息泄露。

### 3.12 友情链接

- 展示站点名称、站点简介、地址和图标。
- 平台管理员可新增、编辑、排序、启用或停用友情链接。
- 外部链接应采用安全的打开方式。

### 3.13 点赞、评论与回复

- 登录用户可对有权访问的博客点赞或取消点赞。
- 同一用户对同一博客最多存在一个有效点赞，重复请求不得造成点赞数异常。
- 登录用户可对允许评论的博客发表评论。
- 登录用户可回复一级评论或其他回复，系统应记录被回复对象和回复关系。
- 评论区采用树状关系或扁平展示加回复引用；首期展示层级上限及折叠规则待交互设计确定。
- 评论和回复展示用户头像、用户名、发布时间及必要的回复对象信息。
- 用户可删除本人发表的评论或回复；删除后如何展示其下级回复应保持上下文可理解。
- 博客作者可隐藏或删除本人博客下的不当评论，也可关闭该博客的评论功能。
- 平台管理员可按平台规则处理违规互动内容，并保留审计记录。
- 内容权限收紧或内容下线后，未获授权用户不得继续查看或新增点赞、评论和回复。
- 点赞、评论和回复操作应提供即时、明确的成功或失败反馈，并防止重复提交。
- 互动接口应具备登录校验、内容权限校验、频率限制、敏感内容处理和垃圾信息防护。
- 可向博客作者及被回复用户发送站内通知；用户可查看、标记已读并配置必要的通知偏好，首期通知范围待确认。

### 3.14 账号安全与平台管理员认证

- 普通用户与平台管理员均支持账号和密码登录，管理员入口可按安全策略独立设置。
- 登录失败时给出明确但不泄露账号状态的提示。
- 支持安全退出和登录状态失效处理。
- 可选支持验证码、双因素认证、密码找回和登录设备管理。

### 3.15 用户创作中心

- 分别展示当前用户的博客和笔记，支持按标题、类型、状态、权限、分类和时间筛选。
- 支持新建、编辑、预览、发布、下线、归档及删除本人内容。
- 支持草稿自动保存或离开页面前的未保存提示。
- 编辑器支持 Markdown 输入及实时预览。
- 博客支持配置标题、摘要、封面、分类、标签、发布时间、权限、是否置顶和是否允许评论。
- 笔记支持配置标题、正文、分类、标签和权限；默认不参与公开推荐。
- 内容状态至少包括：草稿、已发布、已下线。
- 支持定时发布作为后续增强能力。
- 删除操作优先采用可恢复的逻辑删除机制。

### 3.16 媒体资源管理

- 支持上传用户头像、博客封面和正文图片。
- 上传时校验文件类型、大小和安全性。
- 支持查看、复制地址和删除本人未使用的资源。
- 用户只能访问本人媒体库中的非公开资源，正文图片的访问应服从所属内容权限。
- 图片存储方案可选择本地文件、对象存储或图床，技术方案待定。
- 后续可增加压缩、缩略图、格式转换和 CDN 加速能力。

### 3.17 互动管理

- 用户可查看自己收到和发出的点赞、评论及回复。
- 博客作者可查看本人博客下的全部互动，并按博客、互动类型、状态和时间筛选。
- 支持回复、隐藏和删除本人权限范围内的评论。
- 对疑似垃圾内容进行标记或拦截。

### 3.18 站点配置

- 配置网站名称、副标题、简介、头像、图标和页脚内容。
- 配置每页博客数量、默认头像、默认封面、注册开关和互动规则等基础参数。
- 配置社交平台链接、联系方式及友情链接。
- 可选配置备案信息、版权声明、统计代码和 SEO 信息。

### 3.19 数据统计

- 用户侧统计本人博客数、笔记数、草稿数、获赞数、评论数和分类/标签数量。
- 统计本人博客阅读量及热门博客排行，不向普通用户泄露他人的私密统计数据。
- 平台管理员可查看经过权限控制的平台汇总数据。
- 可选展示访问趋势、来源和终端分布。
- 统计口径、隐私策略和第三方统计工具在技术设计阶段确定。

## 4. 页面清单

### 4.1 前台页面

| 页面 | 核心内容 |
| --- | --- |
| 首页 | 站点信息、博客列表、作者信息、分页、推荐内容 |
| 注册/登录页 | 用户注册、登录、找回入口及状态提示 |
| 用户个人主页 | 公开资料、公开博客及个人创作信息 |
| 博客详情页 | 博客正文、目录、作者、权限提示、点赞、评论与回复 |
| 分类页 | 分类列表及当前访问者有权查看的内容 |
| 标签页 | 标签列表及当前访问者有权查看的内容 |
| 归档页 | 按年月聚合的可见博客列表 |
| 搜索页 | 搜索输入、结果列表、空状态 |
| 关于页 | 平台介绍、规则和公开联系方式 |
| 友情链接页 | 外部站点列表 |
| 无权限页面 | 登录引导或无权访问提示，不泄露内容详情 |
| 404 页面 | 页面不存在提示和返回入口 |

### 4.2 用户中心页面

| 页面 | 核心内容 |
| --- | --- |
| 个人资料页 | 头像、用户名、个人简介及公开信息设置 |
| 创作控制台 | 本人博客、笔记、草稿及互动数据概览 |
| 内容列表页 | 按类型、状态、权限、分类和时间查询本人内容 |
| 内容编辑页 | 博客/笔记选择、Markdown 编辑、预览、权限及发布设置 |
| 分类与标签页 | 本人分类和标签的增删改查 |
| 互动中心 | 收到和发出的点赞、评论、回复及通知 |
| 授权管理页 | 指定用户可见内容的授权名单管理 |
| 个人媒体库 | 本人头像、封面和正文图片管理 |
| 账号安全页 | 密码修改、登录安全及账号操作 |

| 页面 | 核心内容 |
| --- | --- |

| 用户管理页 | 用户查询、状态管理及必要的审计入口 |
| 内容治理页 | 违规博客、笔记及媒体内容处置 |

## 5. 核心业务规则

### 5.1 博客与笔记生命周期

1. 用户创建博客或笔记后，内容默认为草稿状态。
2. 草稿仅内容作者本人可查看和预览。
3. 发布时校验标题、正文、分类等必填内容。
4. 发布成功后，仅符合当前权限条件的访问者可查看内容。
5. 已发布内容可修改；修改后应更新最后修改时间，权限变化立即生效。
6. 下线内容不再对其他用户展示，但作者本人仍可管理。
7. 删除内容默认进入当前用户的回收站；永久删除需再次确认。
8. 内容由笔记转为博客时，发布前必须再次确认访问权限和评论设置。

### 5.2 内容可见性

- 首期支持公开、登录可见、指定用户可见和仅自己可见四个等级。
- 博客默认权限应醒目提示，笔记默认仅自己可见。
- 所有详情、列表、搜索、推荐、互动、媒体和统计接口必须遵守内容可见性规则。
- 用户从授权名单中被移除或退出登录后，应立即丧失相应内容访问权限。
- 密码访问、会员等级可见等模式列为后续扩展能力。

### 5.3 数据归属与隔离

1. 每条用户数据必须具有明确且不可伪造的所有者关系。
2. 服务端根据当前登录身份判断数据归属，不接受客户端指定身份作为最终授权依据。
3. 普通用户修改或删除资源时，必须同时通过资源存在性、所有权和操作权限校验。
4. 跨用户查询只能返回公开数据或当前用户已获授权的数据。
5. 批量操作中的每一条数据都需要独立校验，部分失败时应返回清晰结果。
6. 平台管理员执行跨用户处置时必须具有对应角色权限并生成审计记录。

### 5.4 点赞规则

- 点赞主体必须是已登录且状态正常的用户。
- 点赞目标必须是当前可访问、已发布且允许互动的博客。
- 点赞与取消点赞均应具备幂等性，避免重复请求造成计数错误。
- 作者收紧权限、下线或删除博客后，相关点赞不可继续被未授权用户查看或操作。
- 是否允许作者点赞本人博客待产品确认，默认允许但仍只计一次。

### 5.5 评论与回复规则

- 发表评论或回复前，需校验账号状态、内容状态、访问权限及评论开关。
- 每条回复必须关联所属博客、根评论、父级内容、发布者和被回复用户（如有）。
- 删除含有下级回复的评论时，默认保留“该评论已删除”占位，以维持上下文；若整棵讨论均无有效内容，可整体隐藏。
- 博客作者对本人博客下的评论具有管理权，但不能修改他人的评论文本。
- 评论、回复被隐藏或删除后，相关计数应保持一致并避免出现无法访问的跳转。
- 用户不得通过通知、计数或接口错误信息推断无权访问内容的详情。

### 5.6 唯一标识与地址

- 用户、博客、笔记、评论、回复和点赞记录均应具有不可重复的唯一标识。
- 建议支持独立的可读 URL 标识，便于分享和 SEO。
- 用户名与个人主页地址的绑定策略需要明确；用户名修改后应避免旧链接误指向其他用户。
- 修改标题时是否自动修改博客地址，需要在详细设计阶段明确，默认不自动修改以避免旧链接失效。

## 6. 非功能需求

### 6.1 性能

- 常规网络条件下，主要页面应尽快完成首屏展示。
- 博客、笔记、评论和回复列表必须分页查询，禁止一次加载全部数据。
- 图片应支持懒加载，并控制上传尺寸和输出体积。
- 热点公开数据可按需引入缓存机制。
- 缓存必须包含用户身份或权限边界，禁止将私人或受限内容误作为公共缓存返回。
- 具体性能指标在部署环境确定后补充。

### 6.2 安全

- 密码不得明文存储或传输。
- 用户中心和管理接口必须执行身份、角色、资源归属和访问权限校验。
- 对用户输入进行校验和安全处理，防止 XSS、SQL 注入、CSRF、恶意文件上传等风险。
- 登录、点赞、评论、回复和文件上传等接口应具备频率限制能力。
- 内容资源标识不得作为授权依据，应防止越权访问和不安全的直接对象引用。
- 头像及正文图片应校验真实文件类型，不得仅依赖扩展名。
- 内容权限变化后，访问令牌、缓存、搜索索引和临时资源地址不得绕过最新权限。
- 敏感配置不得提交到公开代码仓库。
- 日志不得记录密码、令牌等敏感数据。

### 6.3 隐私与数据保护

- 用户密码、联系方式、登录信息及私人内容按敏感级别进行保护。
- 对外接口只返回当前页面需要的最少字段，默认不公开邮箱、手机号等联系方式。
- 用户头像、用户名和简介的公开范围应明确告知用户。
- 用户有权查看和修改本人资料；数据导出、账号注销及数据删除策略在上线前明确。
- 管理员访问、审核或处置用户数据应可追踪，并限制无业务必要的查看。
- 若接入第三方统计、存储或消息服务，应在隐私说明中明确数据用途和范围。

### 6.4 可用性与兼容性

- 前台采用响应式布局，适配桌面端、平板和手机。
- 支持当前主流现代浏览器，具体浏览器版本范围待定。
- 表单提供明确的校验、成功、失败和加载状态反馈。
- 页面应具备空状态、错误状态和网络异常提示。
- 内容权限在编辑页、发布确认页和详情页应有易识别的状态标记。
- 点赞、评论和回复应优先即时反馈；失败时恢复界面状态并提示原因。
- 用户切换账号或退出登录后，不得残留上一账号的私人内容和编辑数据。

### 6.5 可访问性

- 页面结构和标题层级清晰。
- 关键交互应支持键盘操作。
- 图片提供替代文本配置能力。
- 文字和背景保持合理对比度。

### 6.6 SEO

- 支持页面标题、描述、关键词及规范链接配置。
- 公开博客页和公开用户主页具有独立的元信息和易读地址。
- 登录可见、指定用户可见、仅自己可见以及草稿内容不得被搜索引擎收录。
- 支持生成站点地图和 robots 配置。
- 支持社交分享卡片信息。
- Vue 的具体渲染方案在技术选型阶段结合 SEO 目标确定。

### 6.7 可维护性

- 前后端分离，接口定义清晰且具备版本管理策略。
- 统一返回结构、错误码、日志格式和异常处理方式。
- 核心业务应具备自动化测试。
- 关键配置区分开发、测试和生产环境。
- 数据结构变化应采用可追踪的迁移方案。
- 权限判断应形成统一规则，避免各接口重复实现导致标准不一致。

### 6.8 数据可靠性

- 数据库和媒体资源应建立定期备份机制。
- 应明确备份保留周期、恢复流程和恢复验证方式。
- 对账号状态变更、权限变更、内容发布或删除、授权名单调整和违规内容处置等关键操作保留必要审计信息。
- 点赞数、评论数等汇总值应与有效明细保持一致，并提供异常修复机制。

## 7. 系统边界与架构约束

### 7.1 总体架构

- 前端基于 Vue 构建用户界面，包括公共博客前台、用户创作中心与平台管理后台。
- 后端基于 Spring Boot 提供业务服务和 API。
- 前后端通过 HTTP API 进行通信。
- 数据库、缓存、认证、搜索、文件存储、部署平台等具体方案暂不确定。
- 系统逻辑上至少包含账号与资料、内容、权限授权、互动、媒体和平台治理等业务边界，具体模块拆分方式待技术设计阶段确定。

### 7.2 接口要求

- 接口遵循统一的资源命名、状态码和错误响应规范。
- 列表接口统一支持分页，并按需支持排序和筛选。
- 接口参数应进行服务端校验，不能仅依赖前端校验。
- 公开接口、用户接口与平台管理接口应有清晰的访问边界。
- 获取、修改或删除用户资源时必须基于当前登录身份执行归属与权限校验。
- 点赞、取消点赞及其他可能重复提交的接口应满足幂等要求。
- 接口文档应能随代码同步维护。

### 7.3 待确定技术项

- Vue 版本及前端工程化工具。
- UI 组件库、状态管理、路由和请求库。
- 管理后台与博客前台采用单项目还是多项目。
- 服务端认证与授权方案。
- 用户注册验证、账号找回及会话管理方案。
- 多用户数据隔离与内容访问权限的实现方式。
- 数据库类型及数据访问框架。
- 缓存与全文搜索方案。
- Markdown 编辑器、解析器及内容安全策略。
- 图片和附件存储方案。
- SSR、SSG、预渲染或纯客户端渲染方案。
- 自动化测试、持续集成、部署和监控方案。

## 9. 验收标准（首期）

- 用户能够完成注册、登录、安全退出和密码修改。
- 用户能够上传或更换头像，设置唯一用户名和个人简介，并在个人主页正确展示公开资料。
- 用户能够创建博客或笔记，并完成保存、预览、发布、修改、下线和删除。
- 博客和笔记正文能够正确渲染常用 Markdown 内容和代码块。
- 新建笔记默认为仅自己可见，发布或转换内容时能够明确确认权限。
- 公开、登录可见、指定用户可见和仅自己可见四个权限等级均按规则生效。
- 普通用户无法通过页面、接口参数、资源编号、搜索、媒体地址或统计功能访问其他用户的未授权数据。
- 权限收紧后，已失去权限的用户无法继续查看内容或进行互动。
- 游客能够正常浏览首页、公开博客详情、分类、标签、归档和公开用户主页。
- 游客搜索结果只包含已发布且公开的博客，草稿、私人笔记和受限内容不会泄露。
- 登录用户能够对有权访问的博客点赞和取消点赞，重复操作不会导致计数错误。
- 登录用户能够评论、回复评论及回复其他回复，并正确展示头像、用户名和回复关系。
- 用户能够删除本人评论或回复；博客作者能够管理本人博客下的评论，但不能修改他人评论内容。
- 内容关闭评论、下线或删除后，系统能够阻止新增互动并正确处理已有展示。
- 平台管理员能够管理用户状态和处置违规内容，关键操作具备审计记录。
- 网站在常见桌面和移动端尺寸下能够正常使用。
- 非法访问用户或管理接口时被拒绝，并返回不泄露隐私的合理提示。
- 头像及内容图片上传具备真实类型、大小和安全校验。
- 页面具备必要的加载、空数据、错误和 404 状态。
- 关键业务流程通过约定的功能测试和安全检查。

## 10. 开发阶段建议

### 阶段一：需求与原型

- 确认功能范围、页面结构、视觉方向和内容模型。
- 输出关键页面原型和用户流程。
- 重点验证注册登录、个人资料、博客/笔记创作、权限设置及互动流程。
- 确认站内通知、指定用户授权、账号找回和数据注销等功能的首期范围。

### 阶段二：技术设计

- 完成具体技术栈选型。
- 确定系统架构、数据模型、接口规范、身份认证、数据隔离和内容权限方案。
- 明确点赞幂等、评论回复结构、计数一致性、缓存隔离和媒体访问控制方案。
- 确定部署、域名、HTTPS、备份和监控方案。

### 阶段三：首期开发

- 优先实现用户认证、个人资料、博客/笔记创作、数据归属和四级内容权限闭环。
- 随后实现个人主页、分类、标签、归档、搜索和媒体资源管理。
- 再实现点赞、评论、回复、互动管理与必要的站内通知。
- 最后完善平台管理、站点配置、统计和审计能力。

### 阶段四：测试与上线

- 完成功能、兼容性、响应式、安全和性能测试。
- 准备初始内容、站点配置、隐私声明和错误页面。
- 完成生产环境部署、数据备份及上线验证。

## 11. 后续可扩展方向

- 团队空间、共同编辑和更细粒度的协作权限。
- RSS/Atom 订阅和邮件订阅。
- 博客或笔记定时发布、版本历史和内容回收站。
- 密码访问、分组可见及会员等级可见。
- 全文搜索、相关推荐和个性化推荐。
- 深色模式、主题切换和多语言。
- 用户关注、收藏、第三方登录和完善的消息中心。
- 独立作品集、照片墙、随笔或知识库模块。
- 开放 API、小程序或移动端应用。
- 广告、赞赏、付费内容等商业化能力。
